# schema v3 迁移与本地数据

主键 `campus-survival.save.v3`，备份键 `campus-survival.backup.v3`。旧主键和旧通用备份继续保留，不删除、不回写 v3 进度。

加载顺序：v3 主档 → v3 有效备份 → `campus-survival.save.v2` → `campus-survival.backup` → `campus-survival.save.v1` → 新档。迁移函数在 [migrations.ts](../src/save/migrations.ts)，验证与仓储在 [storage.ts](../src/save/storage.ts)。

## 迁移内容

`migrateV1ToV2` 和 `migrateV2ToV3` 是可重复执行的纯函数，输入不变。先迁移、完整验证，再写入 v3；写入失败仍返回可游玩的内存对象，设置面板可导出。对存储抛错、隐私模式、损坏 JSON 和无效对象逐项回退。

保留全部有效的：

- 绩点、已购角色、当前角色、八项天赋。
- 武器／被动发现、进化发现、已结算局次 ID。
- 声音、画质、震屏、闪光、动态效果、伤害数字、残影与触觉设置。
- 局数、通关、击杀、最高周数。

默认补齐旧 16 武器和旧 12 被动的可用状态，旧 ID 不改名；丁字尺、液氮和四个新被动默认开放。新区域默认开放图书馆、食堂、操场。

仅根据可靠旧统计回填：击杀 ≥500 → 课间运动／羽毛球；最高周 ≥9 或通关 ≥1 → 开题通过／经纬仪＋实验中心；通关 ≥1 → 学期幸存者／夜读花园。无法证明的冻结、盾卫、小 Boss、融合、访问、持有丁字尺击败开题等条件从零累计。不会把调试图鉴发现当作解锁资格。

## 新字段

| 字段 | 内容 |
| --- | --- |
| `unlocks.weapons/passives/regions` | 普通模式可用内容，与发现分离 |
| `achievements` | 14 项进度、完成和已领奖状态，正常结算自动领奖 |
| `discoveredEnemies/fusions/relics/events/regions` | 扩充图鉴发现 |
| `stats.elites/miniBosses/shieldKills/frozen/visits` | 正常模式累计统计 |
| `daily.records/attempts/completedDates` | 本地成绩、尝试、不同日期通关 |
| `settings.quickChest/nickname` | .6 秒快速揭晓和本地昵称 |

成就、解锁、绩点、每日记录和结算 ID 由同一次正常结算对象提交。改变玩法的调试局整体跳过结算写入，但允许旧版本已有的图鉴发现行为。每日借用天赋、角色和内容池不写普通解锁，普通成就和每日成就分开判断。

开始游戏时克隆模式、种子、规则版本、角色、天赋、内容池及区域状态；局外解锁改变不影响正在进行的正常局。调试「本局临时解锁」同步重建本局碰撞与导航并立即转为练习局。

## 校验与恢复

- 仅接受 schema 1／2／3，拒绝未来未知 schema；未来 v3 主键原文保留，使用内存模式，不覆盖它。
- 所有数值必须有限、非负，天赋 0—5、周数 0—22，音量等设置 0—1，记录时间 0—1200 秒、诅咒 0—3。
- ID 仅接受当前定义，集合去重且限长；角色最多 6，武器最多 22，被动 16，区域 6，进化 22，融合 6，事件 6，遗物 6。
- 结算 ID 最多保留 100000，昵称最多 20 字符，原发现最多 44，敌人发现最多 32；导入 UI 文件上限 2MB。
- 每日记录同 ID 去重，按日期／版本分组各取前十，按最新记录日期保留最近 30 个日历日；同分按通关、周数、用时、记录先后排序。系统时间及导入数据仍属于本机数据。
- 有效主档写入前保存上一个有效主档为 v3 备份；坏主档不会污染有效备份。
- 显式点击设置中的两次重置确认会清理 v3 和旧版本键；普通加载、迁移和导入不会清理旧档。

本期继续仅保存局外状态，不提供战斗中途续玩。v3 新进度不能自动回退为旧格式；若需回退，使用备份的 v2 项目与保留的旧键。

## 回放

新回放格式为 `version:2`，包含 `rulesVersion`、`RunManifest`、种子、模拟帧、普通／调试指令和输入。旧游戏 v2 导出的格式 v1 会显示「v3 规则无法保证复现，请使用旧版本查看」，不静默套用新规则。调试面板支持版本检查和新回放导出。
